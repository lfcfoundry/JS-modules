# webkit-driver changelog

What changed in each version, newest first, in plain words. The numbers are explained in [tools/versions/README.md](../../tools/versions/README.md): the API number goes up only when someone using an older copy could be affected.

## 1.1.0 · API 1 · 2026-10-17
Stray processes: killing a test run with SIGTERM or Ctrl-C used to leave 7 processes behind (virtual screen, message bus, driver, browser); now 0 are left (measured in WebKitGTK 2.52.6). Clicks are faster: 20 to 22 ms before, 16.6 to 17.8 ms when the pointer moves (about 17% faster) and 5.8 to 7.6 ms when it is already there (about 70% faster), because press and release now travel in one call. waitForFunction now checks inside the page every frame instead of every 50 ms from Node, so a condition that becomes true after 120 ms was seen after 162 to 164 ms and now after 130 ms; a condition that throws now rejects instead of hanging until the timeout. New launch options (all off by default): deviceScaleFactor (whole numbers; the page sees devicePixelRatio 2 with the same page area), colorScheme: 'dark' and reducedMotion: true (the matching media queries become true), and serve (loads your files through a small local web server so errors thrown while a page loads are reported with their real text; on a test page 2 of 2 load-time errors were caught, versus 0 of 2 from a file:// page). The file grew by 3,316 bytes (973 gzipped). Not measured: Net Flow Map's own 82-check suite with the patch.

Tested in: WebKitGTK 2.52.6 (17 real checks and 7 pretend-driver checks pass; plus the five Apple Press piece checks, the four Net Flow Map demos and the idle-core same-answers run through tests/webkit-shim.js) and GNOME Web 46.5 (the real checks that apply to it pass). Not run: Firefox 158 and ungoogled Chromium 155 (this driver does not drive them) and Net Flow Map's own 82-check suite.

## 1.0.0 · API 1 · 2026-10-17
First version. Starts WebKitGTK 2.52.6 or GNOME Web 46.5 through their own WebDriver and gives Playwright-style page calls (`goto`, `evaluate`, `waitForFunction`, mouse, keyboard, wheel, screenshot, `setViewport`, console and page errors) with no packages. Measured on a cloud container with software drawing: WebKitGTK starts in about 1.8 seconds and its 12 browser checks take about 2 seconds; GNOME Web's take about 8 seconds. It ran the whole Net Flow Map browser test (82 checks, 40 seconds) in WebKitGTK. Where GNOME Web refuses WebDriver input, the mouse and keys are sent as DOM events by script (untrusted events); WebKitGTK uses real input.
