# speed-lab changelog

What changed in each version, newest first, in plain words. The numbers are explained in [tools/versions/README.md](../../tools/versions/README.md): the API number goes up only when someone using an older copy could be affected.

## 1.1.0 · API 1 · 2026-10-17
Runs about a third faster: a default five-step run takes 19.3 s instead of 29.3 s (Chromium 155 and Firefox 158) because each step now records 2.5 s instead of 4.5 s (the 1.1 s warm-up is unchanged); a slowdown of 17 ms or more per frame was caught 5 of 6 times at 2.4 s and at 3.5 s alike, and 20 ms 6 of 6 times. A stalled or hidden page can no longer hang the run: before, a page that stopped drawing frames made it wait forever (stopped by hand after 150 s); now each step gives up 1.5 s after it should have ended. A step that drew fewer than 5 frames, or ran while the page was hidden, is marked disturbed and redone (up to 3 tries), and if nothing could be measured the answer says 'No comparison was possible'; before, 0 fps against 0 fps was reported as 'did not make this device stutter'. Two second looks, each only when needed: the first 'nothing moving' step is measured again when it is clearly slower than the last one (WebKitGTK 2.52.6 and GNOME Web 46.5 draw slowly for up to 2.5 s after the page changes; on 3 fresh page loads out of 3 the first baseline read 39, 42 and 46 fps against 62 for every other step, and the old answer said 'did not stutter'; it now reads 62, 61 and 62), and a load that looks slow is measured once more before it is blamed, with the answer saying so and whether the second pass agreed. Each second look adds 3.85 s and did not fire in 4 of 4 default runs in Chromium and Firefox. New warning: when the device draws only about 30 frames per second with nothing going on, the answer says Low Power Mode or battery saver probably caps every number (wording checked with made-up numbers only, not on a phone). Result steps gain optional again and first fields. The file grew by 3,042 bytes (975 gzipped). 12 checks on the numbers and the answer (was 8) and a browser check with 5 parts (was 2).

Tested in: Node checks; Firefox 158.0 (reports 158.0b5), ungoogled Chromium 155.0.8059.39-1, WebKitGTK 2.52.6 and GNOME Web (Epiphany) 46.5, one at a time, in a real browser (tests/pieces-browser.js speed-lab, 2026-10-17; each passed on the final files here; WebKitGTK and GNOME Web through tools/webkit-driver). Not run: a phone, Safari

## 1.0.0 · API 1 · 2026-10-17
New tool, cut from Apple Press's phone speed test. One button runs a comparison on the device (nothing moving, everything moving, parts switched off) and writes the answer in plain sentences with a copyable table: frames per second, time lost to late frames, stutters over 50 ms, the slowest 5% of frames, how much of the scene was showing. Steps are data (`id`, `label`, `role`, `css`, `setup`). Safeguards from bad runs: it scrolls so half the scene shows under the sticky bar, closes anything covering it, redoes a disturbed step up to 3 times, and warns about heat. At the defaults a 5-step run takes about 30 seconds. Changed from the Apple Press original, which was hard-wired to the game: the steps, the covers, the sticky bar and the scene are options. 17.9 KB (6.6 KB gzipped). 8 checks on the numbers and the answer, plus a real run in Firefox 158 and ungoogled Chromium 155 (five steps, a covering card closed and reported, an unclosable card marking steps disturbed).

Tested in: Node checks where the piece has any; Firefox 158, ungoogled Chromium 155 and WebKitGTK 2.52.6, one at a time, in a real browser (`tests/pieces-browser.js`, 2026-10-17; WebKitGTK 2.52.6 through `tools/webkit-driver`; key down/up and touch were sent as page events or the mouse). Not run: GNOME Web (Epiphany) 46.5, a phone.
