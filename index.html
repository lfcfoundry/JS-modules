What it is and how it works

JS-modules is a set of 49 small browser libraries and tools, each solving one problem met while building LFC Foundry's apps: Apple Press, Fancy, the Banana, Pineapple Defense, Story Editor and Netflow Map.

  • Each module is one file with no dependencies: copy it, load it with a script tag or require, call it.
  • Heavy work runs in WebAssembly inside the same file, usually with a JavaScript fallback.
  • Every folder has a README with limits and comparisons, a demo page, tests and a changelog.

The modules are for developers; the apps built from them need no install and no special knowledge.

Why it exists

Single-file offline apps cannot load code from a server, so any library has to be copied into the file, and its size is part of every download. These modules are plain files with no build step and no dependencies. A module is kept only if it does something the nearest open-source option does not, or does it measurably better, and its README says where the other one wins.

Where it helps

  • Offline or single-file web apps and games.
  • One specific fix without adopting a framework.
  • Low-end phones, where memory and download size are tight.
  • Data-heavy pages (maps, charts, logs) that need compact storage.
  • Higher-end hardware and larger projects: because the code is efficient, it scales up with the project as far as modern browsers allow.

Highlights

One file each

Copy only what you need. No build step, no package tree.

Fast by default

Hot paths run in WebAssembly with SIMD, with plain JavaScript when wasm is missing.

Gives memory back

The heavy modules hand memory back after big jobs, by a trim() call or an idle timer.

Tested in three browsers

Firefox, Chromium and WebKitGTK. Every release names the versions it ran in.

Works with AI helpers

AGENTS.md, llms.txt and modules.json describe every piece for people and assistants.

Files other languages can open

lfc-pack files are read by Python and Go as well as the browser, so data packed in a page is not locked in.

Safe saves in 966 bytes

save-kit-lite keeps checked fields and a backup slot in 966 bytes minified and gzipped, for small games.

Big Excel files, faster

zip-open opens Excel files over 16 MB on the page 3 to 24% faster (cloud Firefox, Chromium, WebKitGTK), with the same results.

Numbers you can check

Every number names the browser and machine it ran on, and slower cases are stated.

Quick start

Save a game safely in three lines.

<!-- copy modules/save-kit/save-kit.js next to your page -->
<script src="save-kit.js"></script>
<script>
  var kit = SaveKit.create({ key: 'mygame', schema: { score: 'num' } });
</script>

Parquet was written natively by pyarrow 26 after a DuckDB 2.0 read of the same JSON (zstd level 3, 4 threads).
