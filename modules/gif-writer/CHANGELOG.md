# gif-writer changelog

What changed in each version, newest first, in plain words. The numbers are explained in [tools/versions/README.md](../../tools/versions/README.md): the API number goes up only when someone using an older copy could be affected.

## 1.1.0 · API 1 · 2026-10-17
Making the palette for a busy animation (a smooth, photo-like animation of 30 pictures, 640 x 480, about 513,000 different colors) now takes about 0.4 s instead of 0.8 s in Node (2.05 times faster), 1.7 times in Firefox 158, 3.0 times in WebKitGTK 2.52.6, 2.95 times in GNOME Web 46.5 and 1.3 times in Chromium 155 (one run of 3 each, so Chromium is rough; a second Chromium run gave 1.4 times). Writing the pictures into the GIF is also about 1.7 to 2.2 times faster for such an animation (Node 1,326 to 599 ms). An animation with few colors (7 colors) is unchanged, about 30 ms for the palette. The palette and the GIF bytes are exactly the same as in 1.0.0: 1,000 random sets of pictures (all kinds, large and small, odd memory offsets, ties) gave 0 different bytes, and 7 fixed scenes are now checked by the module test against what 1.0.0 wrote. How: the color count is kept in one table instead of two, the median cut finds each cut by counting instead of sorting, and the nearest-color searches (palette refinement and the encoder) look outward from the color's green value and stop early instead of checking all 255 colors. The file grows by about 4.5 KB (16,260 to 20,789 bytes, smaller is better).

Tested in: Node 22.22.0 module test (all passed) and tests/gif-writer-browser.js, one browser at a time: ungoogled Chromium 155.0.8059.39-1, Firefox 158.0 (reports 158.0b5), WebKitGTK 2.52.6 and GNOME Web (Epiphany) 46.5, each writing the same bytes as 1.0.0 for 30 fixed fingerprints. Not run: a phone.

## 1.0.0 · API 1 · 2026-10-17
New module, cut from Net Flow Map's GIF maker. It turns pictures drawn on a canvas into an animated GIF, in the browser or in Node, with no libraries. It keeps one color palette for the whole animation (so nothing flickers) and writes only the part of each picture that changed. Measured in Node on 30 pictures of 640 x 400 with a small ball moving on a still background: 23.3 KB in 101 ms, where gifenc 1.0.3 made 159 KB in 152 ms (about 6.8 times larger). When every pixel changes in all 20 pictures: 1.09 MB in 562 ms against gifenc's 1.14 MB in 294 ms (about 5% smaller, about 1.9 times slower). Changes from the Net Flow Map original: a stale comment fixed and the test now lives in the module's own folder (an independent GIF decoder checks every pixel).

Tested in: Node checks; the demo page in Firefox 158, ungoogled Chromium 155 and WebKitGTK 2.52.6, one at a time (`tests/flow-demos.js`, 2026-10-17; WebKitGTK 2.52.6 through `tools/webkit-driver`). Not run: GNOME Web (Epiphany) 46.5, a phone.
