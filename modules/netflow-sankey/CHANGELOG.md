# netflow-sankey changelog

What changed in each version, newest first, in plain words. The numbers are explained in [tools/versions/README.md](../../tools/versions/README.md): the API number goes up only when someone using an older copy could be affected.

## 2.0.0 · API 2 · 2026-10-17
Renamed from river-layout (the module is part of Netflow Map's family now): the folder, the file (netflow-sankey.js) and the browser global (NetflowSankey) changed, nothing else was removed, so a project using river-layout 1.x only has to change those three names. That is why this is 2.0.0 · API 2. Faster, same pictures: for the same links every bar, band, loop and the SVG text equal what river-layout 1.0.0 drew (450 random charts with 40,001 bars and 140,445 bands compared in full, the hand-edit path included, plus 120 hand-made drawings, 7 test charts under 3 option sets and 4 pinned tests). Charts of 66, 102 and 194 links: 7.7, 13.1 and 16.5 ms to 2.0, 3.2 and 4.4 ms in Node (3.7 to 4.1 times faster). A chart of 12,600 links, layout: 666 to 168 ms in ungoogled Chromium 155 (4.0 times), 608 to 105 in Firefox 158 (5.8 times), 558 to 94 in WebKitGTK 2.52.6 (5.9 times), 547 to 91 in GNOME Web 46.5 (6.0 times); drawing it with toSvg: 237 to 100 ms in Chromium (2.4 times), 171 to 78 in Firefox (2.2 times), 165 to 40 in WebKitGTK (4.1 times), 161 to 49 in GNOME Web (3.3 times). Over seven test charts (60 to 31,500 links) layout is 2.8 to 9.2 times faster and toSvg 1.6 to 5.7 times faster in all four browsers. A chart with 400 backward links gains most: 1,046 to 229 ms in Chromium (4.6 times) and 963 to 105 ms in GNOME Web (9.2 times). Fixed: an item named like "d1" (a letter d and a layer number) that also had a link running across that layer drew one of its bands from the wrong spot on its bar, overlapping the others; that is the only picture that changes. Bigger: the file grows from 26,952 to 34,081 bytes (8.9 to 11.6 KB gzipped). 15 checks, 3 more than the 12 before.

Tested in: Node 22 checks (15, about 0.3 s); the same-pictures comparison against river-layout 1.0.0 and the timings of seven test charts in ungoogled Chromium 155.0.8059.39-1, Firefox 158.0, WebKitGTK 2.52.6 and GNOME Web (Epiphany) 46.5, one at a time; the demo page drawn and edited in the same four (2026-10-17). Not run: a phone

## 1.0.0 · API 1 · 2026-10-17
New module, cut from Netflow Map's flow chart. It lays out a flow chart (Sankey diagram) and draws it as SVG, with no libraries. On three made-up charts of 64, 118 and 222 links it left 47%, 49% and 58% of the weighted crossings d3-sankey 0.12.3 left (2,147 against 4,608; 10,840 against 22,131; 35,454 against 61,492), taking 17 to 26 ms against 4 to 7 ms. A chart with a backward link makes d3-sankey throw "circular link"; here it is drawn under the picture. New compared with the Net Flow Map original, which took the app's own drawing format: `layoutFlows` takes a plain list of `{ from, to, value }` links, says how many it ignored, and tells you which of your links each band is; `toSvg` draws it (colors, labels and a title, with all text escaped). 12 checks, about 0.2 s.

Tested in: Node checks; the demo page in Firefox 158, ungoogled Chromium 155 and WebKitGTK 2.52.6, one at a time (`tests/flow-demos.js`, 2026-10-17; WebKitGTK 2.52.6 through `tools/webkit-driver`). Not run: GNOME Web (Epiphany) 46.5, a phone.
