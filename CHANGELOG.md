The full details (numbers, test runs, browsers) are kept privately by the maintainers.

How to read a label: `1.2.3 · API 1`. The API number goes up only when someone using an older copy could be affected; see [tools/versions/README.md](tools/versions/README.md).

## Changes since labels began

- 2026-10-30 · **lfc-pack** 0.2.0 · API 0: New optional `meta` option and `LfcPack.metadata(bytes)` (Python `lfc_pack.metadata(path)`): a small note about the file in its own footer section; older readers skip it. New `LfcPack.unpackRows(bytes, {from, count})` reads just a range of rows by decoding only the blocks that hold them, and `LfcPack.stats(bytes)` reads column facts from the footer. Faster one-column reads (checksum in WebAssembly); `packParallel` hands out one block at a time (same bytes, 7 to 27% faster in a container test) and `warmPack(n)` starts helpers early. New `LfcPack.hash(bytes, kind)`, a file viewer (viewer.html), readers that refuse damaged blocks with a plain message, and an optional `check: 'xxh64'` block check with per-column checks (one-column reads about 40 to 50% faster).
- 2026-10-30 · **lfc-pack** 0.1.11 · API 0: New packStream: feed text in pieces and write each block as it is ready, so packing a big file holds one block of text at a time
- 2026-10-30 · **lfc-pack** 0.1.10 · API 0: New experimental unpackColumns reads flat-row files as typed columns without building row objects.
- 2026-10-29 · **lfc-pack** 0.1.10 · API 0: New experimental unpackColumns reads flat-row files as typed columns without building row objects.
- 2026-10-27 · **text-columns** 0.1.1 · API 0: toRows() keeps a column named __proto__ as its own data, and a header with a repeated name now throws instead of silently dropping a column. Same speed.
- 2026-10-27 · **text-columns** 0.1.0 · API 0: First version: reads CSV and TSV into Float64Array number columns and text columns with a WebAssembly SIMD scan (3 to 11 times faster than common parsers in the container), plain JavaScript fallback with the same answers.
