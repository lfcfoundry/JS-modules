## Changes since labels began

- 2026-10-17 · **zip-open** 1.0.0 · API 1: New module, cut from Net Flow Map's file opener. It opens .zip and Excel .xlsx files in the browser or in Node, with no libraries: text files come out as text, every sheet comes out as a CSV table, and every problem is a plain-words note. Every limit is counted on the bytes that really come out, not on the sizes the zip claims. Measured in Node on a zip of 1 GB of zeros (0.97 MB on disk) whose header says 1,000 bytes: this module refuses it in about 0.05 s using about 47 MB, while fflate 0.8.3 took 3.8 s and returned a 1,000-byte file with no error. New compared with the Net Flow Map original: `read(bytes, entry, limit)` for files that are not text, and a `textExt` option to choose which file endings count as text (before, the list was fixed). The Excel reader is bundled inside, so there is nothing else to include. 14 checks, about 2.6 s.
- 2026-10-17 · **walker-sim** 1.0.0 · API 1: New module, cut from Net Flow Map's simulator. It sends random walkers through a network and reports where they end, how many steps and what it cost, with a 95% range on every result and the exact odds beside them for checking. Runs are repeatable from a seed, however they are cut into batches. Measured in Node on a network of 199 items and 561 links: 100,000 walkers in 57 ms (about 1.75 million a second), and the worst gap to the exact odds fell from 1.74 percentage points at 1,000 walkers to 0.12 at 100,000. New compared with the Net Flow Map original, which was built into the app: `graph` turns a plain list of `{ from, to, weight }` links into the network (an unknown start item is a plain-words error), and the exact solver and what-if sweep run without the app around them. 16 kinds of random number are included.
- 2026-10-17 · **river-layout** 1.0.0 · API 1: New module, cut from Net Flow Map's flow chart. It lays out a flow chart (Sankey diagram) and draws it as SVG, with no libraries. On three made-up charts of 64, 118 and 222 links it left 47%, 49% and 58% of the weighted crossings d3-sankey 0.12.3 left (2,147 against 4,608; 10,840 against 22,131; 35,454 against 61,492), taking 17 to 26 ms against 4 to 7 ms. A chart with a backward link makes d3-sankey throw "circular link"; here it is drawn under the picture. New compared with the Net Flow Map original, which took the app's own drawing format: `layoutFlows` takes a plain list of `{ from, to, value }` links, says how many it ignored, and tells you which of your links each band is; `toSvg` draws it (colors, labels and a title, with all text escaped). 12 checks, about 0.2 s.
- 2026-10-17 · **gif-writer** 1.0.0 · API 1: New module, cut from Net Flow Map's GIF maker. It turns pictures drawn on a canvas into an animated GIF, in the browser or in Node, with no libraries. It keeps one color palette for the whole animation (so nothing flickers) and writes only the part of each picture that changed. Measured in Node on 30 pictures of 640 x 400 with a small ball moving on a still background: 23.3 KB in 101 ms, where gifenc 1.0.3 made 159 KB in 152 ms (about 6.8 times larger). When every pixel changes in all 20 pictures: 1.09 MB in 562 ms against gifenc's 1.14 MB in 294 ms (about 5% smaller, about 1.9 times slower). Changes from the Net Flow Map original: a stale comment fixed and the test now lives in the module's own folder (an independent GIF decoder checks every pixel).
- 2026-10-16 · **storage-probe** 1.1.0 · API 1: The page now also checks IndexedDB (the Story Editor keeps its file memory there), and on the second press it says how often and since when this copy was pressed and that its saved data survived. Two new buttons: Measure free saved-data space (how many entries, the biggest ones, how much room is left) and Save a second copy of this page (one press instead of saving the page twice by hand, handy on a phone). The test now waits for the page instead of sleeping, so a run takes about 2 seconds instead of 6 (5.7 s down to 1.7 s, about 70 percent less), and it has 12 more checks, 26 in all.
- 2026-10-16 · **single-file-tools** 1.1.0 · API 1: Packer: `--encoding bytes` makes a file you hand out about 23 percent smaller (210 KB instead of 272 KB on a 1 MB test game; it works from a double-clicked file, not from a server that forces utf-8 such as GitHub Pages), and Zopfli now defaults to 15 passes, about 3 times faster than the old 60 (1.8 s instead of 5.4 s) for 30 bytes more output, with `--fast` (1.0 s) and `--best`. Pictures: ones with a style inside are now handled (the test game's two biggest pictures were skipped before, saving 45 bytes; now the step saves about 3.6 KB after compression), ones with a script inside or no end are left alone and listed, and `--report` shows the real size saved after compression. Fonts: `--report` lists characters a font lacks, `--costs` shows what each layout feature costs in bytes, and the font type label now says woff2. README has the measured numbers and says which packer to pick.
- 2026-10-16 · **fx-governor** 1.1.0 · API 1: Very slow devices are no longer missed. Before, a device slower than 4 frames a second looked like one endless pause and was never stepped down; now three long gaps in a row count as a slow device, and in a simulation a 3 fps device steps down after 3.6 seconds and a 1 fps device after 5.0 seconds. A window under half the line (under 18 fps by default) now steps down after one window (about 3 seconds) instead of two (about 6 seconds); the new option `severe` sets that share, and 0 turns it off. `choose()` with an unknown name no longer locks, and `release('full')` sets the level and hands control back. README now shows a Try full effects again button and how to remember the level between visits, so a slow phone does not repeat the first 3 to 6 seconds of slow play on every launch. Measured in a simulation with fake frame times, not on a real phone.
- 2026-10-16 · **fuzz-kit** 1.1.0 · API 1: Fixed: a page stuck in an endless loop used to freeze the test run for good (over 100 seconds with a 4-second limit); now the run says "hung" and names the step that froze, in 8 to 11 seconds in Chromium and Firefox. Testing with real keyboard input in Firefox failed on every seed tried (4 of 4) because Firefox does not know the key name "Space"; now 4 of 4 pass. New and optional: `--jobs N` runs seeds in several browsers at once (a slow 16-seed test took 4.7 seconds instead of 12.0 in Chromium, about 2.5 times faster, and 16 instead of 20 in Firefox; each browser uses about 350 MB); `swarm` (`--swarm 0.3`) leaves a random part of the steps out of each run so rare situations show up (on a test game, 15 of 600 seeds found a bug that normal runs never found, 0 of 600, while the common bug turned up 105 times instead of 73; using it on every second seed kept most of both, 95 and 6); `--check-repeat` says in plain words whether a seed plays the same game every time, at the cost of about two extra seeds; `final` is a check that runs once after the last step (for example "undo everything, redo everything, the story must come back the same") and shrinks like any other finding (a failure needing 5 steps was cut from 60 steps to those 5); `Fuzzer.Input.pickVisible` picks a random usable button about 12 times faster on a busy page (0.2 ms instead of 2.4 ms with 400 buttons); `--replay FILE` re-runs a saved short failure with one command (the demo bug replays in 3 steps); `--executable PATH` uses a browser program you name, and `--seeds 1-5,9` accepts lists. Changed: shrinking replays 2 to 9 percent fewer steps and makes about 3 fewer tries, with the same result in 449 of 450 test cases. Everything old works the same. Measured on a 4-core cloud machine in Chromium 141 and 153 and Firefox 157; not yet repeated on Firefox 158 and Chromium 155.
- 2026-10-16 · **frame-kit** 1.1.0 · API 1: `QualityGovernor` no longer ignores very slow devices. Before, a frame gap over 100 ms was treated as a pause and never counted, so a phone under 10 frames a second was never stepped down; now four long frames in a row count as a slow device. In a simulation with fake frame times a 6.7 fps phone is stepped down after about 15 seconds and a 1 fps phone after about 102 seconds (it still counts 100 frames before it decides). New option `stepUp: false` (only ever steps down) and new `lock()` / `unlock()` keep a level the player picked. A single stall still changes nothing.
- 2026-10-16 · **fly-to-mini** 1.2.0 · API 1: New options, all off unless you ask, so a 1.1.0 copy can be swapped for this one. (1) `bar`: give it your sticky bar and the module measures its height and follows it when it changes, instead of you guessing a pixel number (the old default of 130 px suited one game; the demo needed 56). (2) `onVisible` and `steps`: tells your page how much of the big element shows, from 0 to 100 percent, so a game can pause effects when little is on screen. (3) `hysteresis`: with 0.1 the mini goes away at under 50% visible but comes back only above 60%, so scrolling right at the edge no longer starts flights back and forth. (4) `keepFocus`: keyboard focus moves to whichever button is showing when the other hides (before, it was lost). (5) `reducedFade`: where the flight is skipped for reduced motion, the arriving button fades in over 0.15 seconds instead of just appearing. (6) `alert()`: makes the mini blink at most once every 3.5 seconds, for 1.8 seconds, only while it is showing. Two fixes for everyone: the flying copy no longer carries duplicate ids and now shows canvas pictures, and `destroy()` now clears the pop timers it used to leave running for 0.4 seconds. Cost: 5.2 KB to 7.4 KB minified (3.1 KB gzipped, up from 2.2 KB). Checks: 20 to 33 (all pass); the demo ran clean in Chromium 141, 153 and Firefox 157.
- 2026-10-16 · **fly-to-mini** 1.1.0 · API 1: New optional `engine: 'transition'` moves the element with the browser's View Transitions API (the same 440 ms arc, tilt and squash) and lets the browser draw it, instead of the module animating a copy every frame. The flight stays the default, and browsers without the API use it automatically; nothing existing changes. Checked in Chromium 141 (names set and cleared, the 440 ms move, the zigzag case); not yet judged by eye on a phone or in Firefox.
- 2026-10-16 · **env-probes** 1.1.0 · API 1: Faster checks: the clock check now stops after 3 clock steps instead of 8 (in Chromium, 8 steps took about 0.8 ms and stopping after 2 took about 0.2 ms with the same answer), and the canvas check writes its test patch with one call instead of 128 (0.2 to 0.8 ms on the first call instead of 1.6 to 2.8 ms, 3 to 8 times faster, still reading back exactly). New: `canvasNoise()` says how big canvas noise is, `framed()` says whether the page sits inside another page, `capabilities()` lists which newer browser features work, plus hover, any-hover and reduced-transparency questions. `explain()` now says so when saving is blocked inside a frame. The demo is now a one-button device check page with a copy-report button. Everything old answers the same as before.
- 2026-10-16 · **canvas-probe** 1.1.0 · API 1: The probe slows the game less: on a test frame of 5,500 canvas calls it added 2.3 ms instead of 3.7 ms to a 3.1 ms frame (about 40 percent less extra time in one run, up to 60 percent in another, in Chromium 141), because it now reads the transform once per draw. New: `probe.check(limits)` gives a pass or fail with plain-words problems (leaks, restore without save, source overhang, growing paths, and a calls-per-frame ceiling) so a game needs no checking code of its own; the report has a per-frame total of calls; and `install({ deep: true })` counts draws made with a filter, a shadow or a blend mode, the ones that cost the most. README now explains the rejected-style-write and method-name limits and says to run games with their quality governor off while the probe is on. The code is the same size (12,672 against 12,678 bytes minified before the new options).
