## Changes since labels began

- 2026-10-17 · **zip-open** 1.0.0 · API 1: New module, cut from Net Flow Map's file opener. It opens .zip and Excel .xlsx files in the browser or in Node, with no libraries: text files come out as text, every sheet comes out as a CSV table, and every problem is a plain-words note. Every limit is counted on the bytes that really come out, not on the sizes the zip claims. Measured in Node on a zip of 1 GB of zeros (0.97 MB on disk) whose header says 1,000 bytes: this module refuses it in about 0.05 s using about 47 MB, while fflate 0.8.3 took 3.8 s and returned a 1,000-byte file with no error. New compared with the Net Flow Map original: `read(bytes, entry, limit)` for files that are not text, and a `textExt` option to choose which file endings count as text (before, the list was fixed). The Excel reader is bundled inside, so there is nothing else to include. 14 checks, about 2.6 s. Tested in: Node checks; the demo page in Firefox 158, ungoogled Chromium 155 and WebKitGTK 2.52.6, one at a time (`tests/flow-demos.js`, 2026-10-17; WebKitGTK 2.52.6 through `tools/webkit-driver`). Not run: GNOME Web (Epiphany) 46.5, a phone.
- 2026-10-17 · **webkit-driver** 1.0.0 · API 1: First version. Starts WebKitGTK 2.52.6 or GNOME Web 46.5 through their own WebDriver and gives Playwright-style page calls (`goto`, `evaluate`, `waitForFunction`, mouse, keyboard, wheel, screenshot, `setViewport`, console and page errors) with no packages. Measured on a cloud container with software drawing: WebKitGTK starts in about 1.8 seconds and its 12 browser checks take about 2 seconds; GNOME Web's take about 8 seconds. It ran the whole Net Flow Map browser test (82 checks, 40 seconds) in WebKitGTK. Where GNOME Web refuses WebDriver input, the mouse and keys are sent as DOM events by script (untrusted events); WebKitGTK uses real input.
- 2026-10-17 · **walker-sim** 1.0.0 · API 1: New module, cut from Net Flow Map's simulator. It sends random walkers through a network and reports where they end, how many steps and what it cost, with a 95% range on every result and the exact odds beside them for checking. Runs are repeatable from a seed, however they are cut into batches. Measured in Node on a network of 199 items and 561 links: 100,000 walkers in 57 ms (about 1.75 million a second), and the worst gap to the exact odds fell from 1.74 percentage points at 1,000 walkers to 0.12 at 100,000. New compared with the Net Flow Map original, which was built into the app: `graph` turns a plain list of `{ from, to, weight }` links into the network (an unknown start item is a plain-words error), and the exact solver and what-if sweep run without the app around them. 16 kinds of random number are included. Tested in: Node checks; the demo page in Firefox 158, ungoogled Chromium 155 and WebKitGTK 2.52.6, one at a time (`tests/flow-demos.js`, 2026-10-17; WebKitGTK 2.52.6 through `tools/webkit-driver`). Not run: GNOME Web (Epiphany) 46.5, a phone.
- 2026-10-17 · **test-isolation** 1.0.0 · API 1: New tool, cut from Apple Press's speed-test page. It puts a prefix in front of every localStorage (and, if asked, sessionStorage) key on a test page, so a speed test, a random-play run or any test build never reads or overwrites the real saved game; its own keys never mix with the real ones. 4.7 KB; `snippet()` gives the same thing as a 641-character inline script for the top of `<head>`. Real localStorage check in Firefox 158 and ungoogled Chromium 155: the real save stayed untouched while the page wrote its own, and `clear()` removed only the prefixed keys. 6 checks on a fake Storage. Found while testing: Firefox does not keep keys in the order they were written, so `key(i)` order must not be relied on (documented). Tested in: Node checks where the piece has any; Firefox 158, ungoogled Chromium 155 and WebKitGTK 2.52.6, one at a time, in a real browser (`tests/pieces-browser.js`, 2026-10-17; WebKitGTK 2.52.6 through `tools/webkit-driver`; key down/up and touch were sent as page events or the mouse). Not run: GNOME Web (Epiphany) 46.5, a phone.

Cost: 5.2 KB to 7.4 KB minified (3.1 KB gzipped, up from 2.2 KB). Checks: 20 to 33 (all pass); the demo ran clean in Chromium 141, 153 and Firefox 157. Tested in: 33 Node checks; the demo ran clean in Chromium 141, Chromium 153 and Firefox 157. Not run: Firefox 158, ungoogled Chromium 155, WebKitGTK, a phone.
