- 2026-10-18 · **pcodec-js** 1.0.0 · API 1: First release, as its own module: Pcodec, a number compressor, for web pages, one file, no build step. It follows an earlier add-on for the object compressor that was never published as its own file. WebAssembly is required, with no plain-JavaScript backup (Jawad's decision). What is new compared with that add-on (440,757 B, 159,050 B gzipped). Lower is better for sizes, times and memory. - **Tuned unpack loop.** One patch to Pcodec 1.0.4 removes the per-number bounds checks in the loop that reads each number's extra bits (about 40% of unpack time). Unpack is lower by about 6% on average: reader, view, ns per number, Chromium / Firefox / WebKitGTK / GNOME Web, two runs: 12.66 to 12.13 and 12.56 to 12.88 (a tie, within noise) / 13.34 to 12.37 and 13.01 to 12.37 / 15.30 to 13.34 and 14.32 to 13.34 / 14.64 to 13.34 and 13.99 to 13.01. The SIMD reader gains 7% / 3% / 2% / 11%. Files are about 1% smaller. Output and written bytes are identical; packing speed is unchanged. Two other changes tried (delta decode in one pass, decimal join without a branch) gave no gain and were dropped. Details: `RESULTS.md` section 4c. - **Unpack-only file.** 168,183 B (68,390 B gzipped) against 440,757 B (159,050 B gzipped): 2.6 times smaller raw, 2.3 times smaller gzipped. The wasm program went from 326,822 B to 112,851 B. - **Packer file is built for speed, so it is a bit bigger.** 468,019 B (184,685 B gzipped): 6.8% larger raw, 16% gzipped. - **Packing is faster.** 12 columns: 85 against 96.3 ms in Chromium (12% faster), 90 against 107 in Firefox (16%), 93 against 107 in WebKitGTK (13%), 88 against 105 in GNOME Web (16%). Same bytes out.
